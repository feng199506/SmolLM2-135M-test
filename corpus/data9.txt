一、当前主线判断

新的中心已经不是 UID235，而是 UID20/v00。

Claude 的初步结果显示：

UID20 与 UID235 使用相同的五个模型 checkpoint；
优势主要可能来自控制程序、配置和恢复逻辑；
因此“程序策略优化”确实可以在不重新训练模型的情况下超过旧冠军；
后续应以 UID20 为候选新基准；
UID235 的大量诊断数据继续保留，用于理解问题和筛选机制。

SC2B 当前状态：

六对 mean +0.0425，CI 下界略高于 0；
两个 seed 有大收益，多数接近 0；
TIMEOUT 合计 +1，collision −3；
结论是分数信号有希望，但不满足预注册安全门槛；
保持默认关闭，不继续围绕 UID235 调 0.40。
二、短期可执行策略

短期策略原则：不大规模训练、模块化、默认关闭、少量配对实验、快速回滚。

A. 新冠军继承与验证

优先级最高。

不是马上修改 UID20，而是：

验证 UID20 artifact 与官方 model 966 的绑定；
验证官方分数；
做最小 instrumentation equivalence；
少量分层基线运行；
以 UID20 替换 UID235 成为开发基准。

这是当前最可能快速提升整体起点的动作。

B. Mountain route bounds 测量与条件裁剪

发现的冲突：

learned route 范围：120m；
mountain world 配置：75m；
mass grid：120m；
最大 ring：118m；
learned route 在 mountain 没有执行 _in_bounds。

正确顺序：

只记录 waypoint 是否越过真实任务边界；
统计越界 waypoint 与 TIMEOUT/低分的关系；
有证据后再做条件 clamp；
不能直接假定 75m 正确。

这是目前最强的短期诊断候选之一。

C. Mountain median pad refinement

UID20/v00 新增机制。可能通过多个 noisy detection 的中位数减少错误 pad 位置，特别适合 clue noise 和山体遮挡。

需要验证：

是否在 UID20 中真正启用；
对 mountain 的 pad 位置误差是否降低；
是否延迟 landing commitment；
是否改善 TIMEOUT，而不增加误锁。
D. Orphan waypoint/lane redistribution

当某架无人机失败、完成或无法继续时，将遗留路线/目标交给其他无人机。

UID235 已有部分 orphan-lane takeover，UID20 又增加 route-level orphan waypoint pool。需要比较：

新机制是否真正补足了旧逻辑；
是否会造成多机争抢同一 pad；
对 N=6/8 是否特别有效。
E. Boxed-only steering（SC2B）

机制本身仍有价值，但不能按当前版本推广。

后续可能的改进方向不是直接调 keep，而是：

更准确限定 boxed 状态；
结合剩余时间；
只对仍有安全水平间隙的方向保留动作；
避免把本来会快速失败的轨迹拖成 TIMEOUT；
在 UID20 上重新验证可迁移性。

状态：PROMISING_BUT_SAFETY_FAILED，暂时关闭。

F. Spiral re-seed

路线耗尽后，UID235/UID20 可能退回 clue-relative spiral。候选机制是：

检测 SEARCH + route exhausted + 长时间无新覆盖；
将 spiral 角度跳到未搜索的方向；
每架无人机最多一次；
不直接修改模型动作。

比 SC2R waypoint skip 更符合已观察到的 no_next_waypoint。

G. Tilt-adaptive reference governor

来自其他 GitHub 谱系。

根据 tilt、速度和动作变化限制控制指令：

高倾斜时降低水平激进程度；
平稳时保持速度；
防止动作突变引发 TILT/碰撞。

风险是过度平滑会降低速度分。适合做单独小实验，不能和 SC2B 混合。

H. Landing lock / commitment control

接近 pad 后减少重新搜索、目标切换或横向振荡：

pad 已确认后短期锁定；
明显失效才释放；
descent 阶段限制重新分配；
防止“已经接近却重新离开”。

需要更完整的 APPROACH/COMMIT 失败阶段遥测。

I. Action-contract guard

UID20 中的新机制，主要是保险：

非有限动作拒绝；
shape/dtype/bounds 检查；
异常时确定性安全动作；
避免整个 seed 因无效动作直接失败。

它不一定提升正常 episode 分数，但可以减少极端失败。

J. Thread pinning

torch.set_num_threads(1) 与官方单线程环境一致：

减少线程争抢；
提高延迟稳定性；
降低 validator strike 风险。

属于低风险工程优化，应纳入新基准，但必须证明动作不变。

三、程序和推理优化

官方环境是 CPU-only、2 CPU、6GB、有效单线程。优化重点不是本地 GPU，而是官方 CPU 推理。

低风险、优先检查
模型只加载一次；
全路径 model.eval()；
全路径 torch.inference_mode()；
固定 torch/OMP/MKL 单线程；
减少 NumPy↔Tensor 复制；
避免重复 dtype/shape/normalization 转换；
缓存静态 Tensor、mask 和常量；
向量化逐 drone Python 循环；
PadNet 多无人机 batch 前向；
DONE drone 避免无意义后处理，但不能改变其他 drone 输入语义；
延迟加载非当前地图所需模型；
清理重复 import、模型构建和配置解析。
中等风险
TorchScript；
ONNX Runtime CPU；
算子融合；
固定/动态 N 图优化；
PadNet 单独转换，而不是一次转换全部模型；
更紧凑的模型文件加载与内存映射。

必须验证：

PT 与 ONNX 输出误差；
最终动作字节或容忍范围；
阈值附近是否翻转 detection；
动态 N=2–8；
官方容器依赖；
包大小 ≤50MiB。
高风险、后置
INT8 量化；
模型剪枝；
FP16 CPU；
跳帧推理；
降低输入分辨率；
改变检测阈值；
换模型架构。

这些可能改变模型能力，应视为算法实验，而不是纯程序优化。

需要注意：官方分数主要由仿真时间、成功和安全决定，wall-clock 推理加速通常不直接增加分数。它的价值主要是减少 RPC strikes、资源峰值和不稳定执行。

四、中期策略
1. Breadcrumb/visited-space memory

v00 已创建 _crumbs 但没有真正消费。可以用于：

标记已经搜索区域；
避免重复 spiral；
选择未覆盖方向；
为 route exhausted 提供恢复依据。

这比完整 SLAM 简单得多。

2. 轻量 occupancy/cost map

利用已有 depth + 精确 state：

局部障碍栅格；
衰减式历史；
不重新做定位；
为短期路径、绕障和 coverage 提供依据。

重点是“记忆/建图”，不是 SLAM 定位。

3. Receding-horizon route planning

当前 route 只规划一次。中期可改为：

定期根据当前位置、剩余时间、覆盖历史重新规划；
只有新信息出现时 replan；
commit 前验证新路线；
避免 SC2P 那种同一 clue、同一模型的一次性重复求解。
4. Mountain GoalPosterior/mass memory 修复

不能直接把 mountain 开关打开，因为以前有负结果。

应加入：

remaining-time veto；
coverage benefit 判断；
pad 已发现时禁止重规划；
接近 descent 时停止切换；
仅在预期节省时间时启用。
5. 更完善的平台所有权

包括：

pad claim；
release；
failed-drone blacklist；
orphan target takeover；
contention detection；
距离与到达时间联合分配；
landing commitment 后不轻易抢占。
6. Fleet-size-aware lane assignment

N=2–8 动态变化，应根据：

fleet size；
pad 数量和间距；
route capacity；
predicted time-to-pad；
failed/landed drones；
mountain corridor 宽度；

动态决定路线和平台分配。

7. Collision attribution 与 fleet guard

目前碰撞 partner 经常是 unknown。先修复：

teammate；
static obstacle；
failed drone obstacle；
platform/descent contact。

之后再决定是：

separation radius；
velocity obstacle；
lane spacing；
descent exclusion zone；
failed-drone avoidance。
8. 参数优化

只有机制独立验证后才使用：

Sobol/LHS 初始覆盖；
BO/TPE/BOHB；
固定 development seeds；
paired evaluation；
多目标：score、TIMEOUT、collision、计算开销；
参数冻结后进入 holdout/OOD。

可优化参数包括：

boxed keep；
route clamp；
stagnation window；
spiral reseed angle；
landing lock；
separation radius；
governor 强度；
memory decay。
五、长期策略
A. 重新训练 Mountain RoutePlanner

Claude 发现 mountain route head：

utility 最低；
样本仅约 281；
其他地图约 4000；
waypoint 只有 5 个；
clue-relative；
没有 coverage/depth/visited-space输入。

长期可以：

补充 mountain 数据；
加入当前位置、depth 特征、coverage；
支持动态 N；
重新训练路线头；
单独保留其他地图权重。
B. 学习型 coverage/belief state

将：

depth；
visited area；
pad detection；
teammate state；
remaining time；

融合为短期 belief/coverage 表示。

C. Learned multi-agent coordination

包括：

图网络协调；
learned separation；
pad allocation；
route arbitration；
failed-drone recovery。

Claude 找到的 ONNX graph pack 中已有 swarm_sep、swarm_coord2 节点，可作为结构参考，但尚未执行验证。

D. MARL 或重训练整体策略

成本高，必须：

单独开发 seeds；
domain randomization；
paired baseline；
odd-N；
OOD；
官方 CPU 推理验证；
防止训练只适配公开地图。
E. 完整地图与长期记忆

优先级高于完整 SLAM。因为环境已经提供位置状态，更需要的是：

障碍地图；
搜索覆盖；
pad belief；
teammate/failed-drone动态障碍；
路线历史。
F. 完整 SLAM / 视觉里程计

当前不是主要瓶颈：

state 已提供位置；
本地排行模型没有使用完整 SLAM；
会增加计算和工程风险。

只有未来任务隐藏位置或存在明显定位噪声时才升级。
